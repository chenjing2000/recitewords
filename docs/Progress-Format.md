# 学习进度格式

本方案已取消 `review_count` 和 `position`。进度只记录各单词当前的学习状态，不记录复习次数或上次复习位置。结合已确认的删除 `wid`，单词以去除首尾空白并经过 Unicode casefold 的 `word` 作为关联键。

**当前程序只接收版本 2。版本 1、旧对象型词状态、旧会话字段均不兼容；读取失败会提示错误并禁止提交，不覆盖原文件。**

## 文件位置

仍保存于单词本所在目录的 `userdata/<单词本文件名去掉扩展名>.progress.json`。目录或文件不存在时自动初始化。此名称由实际文件名决定，不由单词本 JSON 的 `name` 决定。

## 保存内容

保留 `application` 和 `schema_version` 用于识别文件与校验版本；学习数据只保存 `words` 中的当前状态。新结构采用版本 2，与旧结构区分。

```json
{
  "application": "ReciteWords",
  "schema_version": 2,
  "words": {
    "loyalty": "Familiar",
    "cognizant": "Unknown",
    "address": "Mastered"
  }
}
```

状态值为 `Unknown`（不懂）、`Familiar`（认识）、`Mastered`（掌握）。没有评价记录的词属于未学，不必写入 `words`。重新评价只覆盖对应状态。首次初始化时 `words` 为 `{}`。

不再保存旧 `session` 对象中的筛选、队列、`position` 或完成标记；这些都是本轮会话信息，而不是单词当前状态。无需用另一个字段保存当前单词来替代 `position`。

## 删除位置后的行为

旧 `position` 是本轮筛选队列中的索引，从 0 开始，`0` 对应第一词。删除 `wid` 并不会使这个索引失去意义；本次删除是因为用户不需要保存学习位置。

程序运行期间仍需在内存中维护当前索引、固定队列和完成状态，以支持上一词、下一词、评价后前进及完成后后退；这些数据不写入进度文件。

每次打开单词本恢复单词状态，从“全部”分类第一词建立新队列，不恢复上次的位置和队列。选择其他分类时从该分类第一词开始。评价成功保存后刷新分类数量；导航无需写入进度文件。评价保存失败时回滚状态与位置，不前进。

## 版本与旧文件

进度模型仅保存状态，ReviewSnapshot 仅保存内存中的队列和索引，供保存失败回滚使用。导航和分类选择不写进度；评价失败恢复完整会话。

不提供旧记录读取、迁移、重置或恢复入口。需要开始使用新格式时，由用户自行维护旧记录并提供版本 2 文件，或移走旧文件后让程序初始化。程序不会自动删除旧文件或静默清空其状态。

顶层只接受 application、schema_version、words。words 的值只接受上述三个大小写准确的状态字符串，键必须已经去除首尾空白并经过 Unicode casefold，不接受数字、对象或未标准化的键。

单词本、音频索引、应用设置有各自独立的格式规则，不受本文件的版本 2 限制。应用仍记住上次文件夹和单词本，窗口设置不变。
