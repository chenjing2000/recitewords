# 代码审查与整改（2026-10-05）

## 结论

当前简单 WPF + MVVM、JSON 文件和手工组装适合 ReciteWords。模块职责基本清楚，没有需要整体重写的问题。本轮只修正确认的问题并删除升级后遗留的参数和回调；文件格式、评价规则、音频命名与释义切换行为保持不变。

## 模块、内聚与耦合

| 模块 | 审查结论 |
|---|---|
| Models / Common | 数据类不读文件或操作 UI；JSON 校验、拼写比较、音频 stem 转换是实际共享的具体工具。 |
| Storage | 单词本只读，进度和设置分别保存；临时文件加替换保证写入失败时不破坏原文件。进度仓库不再接收用不到的整本词库。 |
| Review | 独立管理状态、固定队列、导航和分类计数；不依赖文件路径、播放器或 WPF。快照的深复制用于保存失败回滚，有明确用途。 |
| Audio | 目录按首次 stem 资格查找本地文件，播放器只负责播放及错误通知；不负责学习状态或读取词库 JSON。 |
| ViewModels | 通过六个服务接口编排打开、评价、保存与播放；回滚逻辑直接放在 Rate 中，未增加通用事务层。 |
| Views | 只处理布局、目录对话框、提示计时及 FlowDocument 排版；例句按钮调用 ViewModel，不直接打开音频文件。 |
| Platform | Windows 显示器、DPI 和窗口约束集中在一个具体类中；Win32 调用不进入业务模块。 |
| Tests / tools | 测试夹具和资源生成脚本有实际用途，不属于交付程序运行依赖。 |

接口按实际服务边界设置，并用于替换文件仓库和播放器进行测试；无需为数据类、辅助函数或每个控件增加接口。当前没有数据库、依赖注入容器、事件总线、通用仓储、多层继承或业务反射。ViewModel 编排多个服务是其职责，尚无需再拆分。

## 必要修正

1. **未记住没有有效单词本的目录。** 原来仅在成功打开词库时保存 Folder。现在扫描完成但没有有效词库时，也保存所选目录并清空旧的词库文件名；重新启动仍使用该目录。用真实设置文件复现并验证。
2. **学习记录错误被坏词库提示覆盖。** 原来打开词库后才发出扫描警告，覆盖了进度读取失败提示。现在先报告跳过的文件，再打开选中的词库；后续记录或设置错误保持优先显示。损坏进度仍不覆盖，评价仍被禁用。
3. **超长音标突破窗口宽度上限。** 原来直接将音标行完整宽度作为窗口最小宽度；300 字符的合法音标使 MinWidth 大于 MaxWidth。现在为两个喇叭和间距保留空间，限制标签最大宽度；超长音标省略显示，悬停可查看完整内容。窗口仍遵守屏幕宽度 70% 上限，普通音标的布局不变。真实 WPF 测试覆盖宽度约束、喇叭可见及移动窗口。

## 简化与可读性

- 删除 ReviewSession.Start 的起始序号参数及夹取逻辑；每次选择分类始终从第一个词开始。内存 Position 仍用于导航与回滚，不写入进度文件。
- 删除 IProgressRepository.LoadOrCreate 中未使用的 WordList 参数；同步实现、调用者和测试，减少无意义的模块数据传递。
- 删除仅被 Rate 调用的 Update(Action) 包装，直接表达快照、评价、保存、失败回滚、发布当前词的顺序。
- pos 已经在输入层作为必填字段校验，显示层不再重复判断是否缺失。
- 两个音标属性中的嵌套三元表达式改为直白分支；保留少量重复，不引入通用属性框架。窗口尺寸计算保留有意义的中间变量。
- 修正 casefold 注释，说明其用于当前词库重复检测和进度键，不暗示仍兼容旧进度文件。

普通可空类型、using 资源释放、事件、短命令回调、WPF 依赖属性和必要 Win32 结构保留；它们直接服务于生命周期、绑定和系统窗口行为。BigInteger 对应 schema_version 可以为任意正整数的明确要求。测试中的 LINQ 和元组用于查找控件、组织样本，未搬入业务代码。没有为了消除少量重复而增加抽象。

## 验证限制

本次单屏验证不能替代混合 DPI 多显示器验收。极小工作区无法同时容纳全部固定控件和指定内容高度，需在目标设备确认。多个实例同时修改同一本词库的进度仍可能互相覆盖；当前未增加多进程协调。播放检查验证解码和完成事件，不能代替发音质量试听。
