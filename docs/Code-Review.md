# 代码审查与整改

## 结论与边界

现有 WPF + MVVM 和手工组装方式适合该程序。保留界面、文件读写、复习和音频的分离，以及用于替换真实文件/播放器进行测试的小接口。没有必要引入数据库、依赖注入容器、通用仓储、事件总线或更多继承层。

| 模块 | 职责及依赖 | 评价 |
|---|---|---|
| Models | 单词、词义、进度、设置数据 | 不承担读写或界面工作，保持简单可变属性 |
| Common | JSON 字段校验和 Unicode 拼写比较 | 两种被文件与音频模块实际共同使用的具体工具，无通用框架 |
| Storage | 词库扫描/加载、进度校验/原子写入、设置读写 | 通过小接口提供服务，独立于 WPF |
| Review | 固定本轮队列、评价、重评、导航、数量、快照回滚 | 只依赖 Models，保持单一状态所有者 |
| Audio | 索引解析、文件匹配、媒体播放 | 索引依赖 Common，播放器承载 WPF MediaPlayer；不依赖词库仓储实现 |
| ViewModels | 编排读取、保存、评价、提示与播放 | 文件和播放器通过接口访问，Dispatcher 仅以小回调传入 |
| Views | 排版、缩进、文件夹对话框、提示计时、界面尺寸 | 与 ViewModel 绑定；未把文件读写或复习规则搬到界面 |
| Platform | Windows 显示器、DPI、窗口上下限 | Win32 调用隔离，界面只调用两处入口 |

## 必要问题与修正

1. 不完整 Unicode 转义：已复现合法 JSON 语法中的 `\ud800` 使 GetString 抛出未处理 InvalidOperationException。字段值、字符串数组和字段名现在转换为有上下文的 InvalidDataException，扫描会报告坏文件并继续加载其它词库。未知字段的内容仍不导入。
2. 例句音频配置的词条值不是数组时原来直接跳过，不能区分损坏配置和缺失音频。现在报告格式错误，清空该无效索引并禁用对应播放；不阻断词库或另一份音频索引。

## 简化与职责调整

- 拼写比较从 WordListRepository 移入 Spelling；共享 JSON 校验移入 Common。Audio 不再借用具体词库仓储。
- WordListEntry 只存路径、名称；扫描仍完整校验每个文件，但不保留全部词库内容。打开时重新读入当前词库，避免一份词库被重复持有。
- FilterChoice 单独成文件，不再混在主 ViewModel 文件末尾。
- 删除已无调用的 SuggestStart 和原界面位置属性；保留进度文件中的 position，文件格式不变。
- 用轻量 Filter 属性读取当前分类，避免为了读取一个枚举而深拷贝整份学习进度。
- GetCount 直接统计，不再为五个筛选项创建五份临时队列；复习快照仍保留必要的深拷贝，保证保存失败回滚与外部修改不会污染内部状态。
- 缺少可选数组时直接返回空列表，不再解析并克隆临时 `[]` 文档。
- 复杂的匹配和嵌套三元判断改成直白分支；对象构造使用明确类型。普通属性、资源释放、可空类型、事件及 WPF 命令回调保留，因为它们有实际用途。
- 删除旧 TextBox/AccentButton 样式与不再使用的生成喇叭资源；原始用户图标保留。没有增加通用抽象来消除少量重复。
- 窗口布局下限仅在数值改变时赋值；去掉保存失败路径中的重复全局通知。
- 统一源代码空白格式。测试中用于查找 WPF 元素的 LINQ 和数据样本元组保留在测试项目，不进入业务实现。

## 验证与实际限制

完整检查覆盖输入格式、Unicode、坏文件隔离、进度独立保存/恢复/损坏保护、保存失败回滚、固定队列及重评、筛选数量、延迟自动读词取消、音频匹配、真实 WPF 排版/缩进/滚动/提示计时、窗口上限及本地 WAV/MP3 解码完成。最新测试结果及清理记录见下方最终验证。

混合 DPI 多显示器需在对应设备上验收；本次单屏验证不能代替它。没有新增自动恢复、自动复习、文件监听或多进程进度协调。多个实例同时改同一个进度文件仍可能互相覆盖，当前程序按一个词库在一个实例学习的用法运行。
