# 代码审查与整改（2026-10-13）

## 结论

现有 WPF + 简单 MVVM、JSON 和手工组装适合本程序。模块职责和主要数据流清楚，没有需要整体重写或新增框架的问题。本轮保留现有接口、文件格式、学习规则、显示和键盘行为，只修正确认的问题并清理生成文件。

## 模块、内聚与耦合

| 模块 | 主要职责与审查结论 |
|---|---|
| Models | 保存词库、设置、学习状态等数据，不读文件、不控制界面。 |
| Common | 共享 JSON 字段校验、拼写 casefold 和音频 stem 转换；都是正在使用的具体工具。 |
| Storage | 单词本只读；进度和设置独立持久化。使用临时文件写入后替换，保存失败不破坏原文件。 |
| Review | 按状态建立固定队列，负责导航、评价、统计和内存快照；不依赖路径、音频或 WPF。 |
| Audio | AudioCatalog 只查找本地文件并处理首次 stem 资格；WpfAudioPlayer 只负责播放、停止和错误通知。 |
| ViewModels | MainViewModel 编排打开、评价、保存和播放，通过六个服务接口调用模块；不重写文件解析和复习算法。 |
| Views | MainWindow 处理布局、目录选择、提示计时及快捷键；DefinitionView 负责释义排版和音频按钮，不修改学习状态。 |
| Platform | WindowBounds 仅恢复启动位置和尺寸，集中必要 Win32 调用；不再设置最大尺寸或接管最大化。 |
| Tests / tools | 测试覆盖真实模块和 WPF 行为；资源生成脚本仅用于开发，不属于发布程序的运行依赖。 |

六个接口对应真实边界，并支持文件错误、播放和回滚测试；不为数据类或每个辅助函数增设接口。MainViewModel 编排多个服务是其职责，当前规模无需进一步拆分。未使用数据库、DI 容器、事件总线、通用仓储、业务反射或复杂继承体系。

## 必要修正

**启动时的配置错误被后续目录提示覆盖。** 配置损坏时，构造函数先发出读取错误；Initialize 随后扫描空目录，新的“没有有效单词本”提示覆盖前一个错误，用户无法知道设置为什么不再保存。现在保留配置读取错误并合并后续启动提示，仍禁止覆盖原配置，提示栏仍按原规则显示 5 秒。新增回归检查先复现失败，再修复通过。

## 推荐整改与简化

- 导航边界由 ReviewSession 统一判断。原 Navigate 重复检查前后边界，却忽略 Move 的返回值；未发生移动时仍可能清空释义、排队重播。现在仅在 Move 成功后发布当前词，保留命令的可用状态判断。回归检查验证无效移动、首尾边界不会清空释义或增加播放请求。
- 取消窗口最大尺寸后，若干测试仍比较 ActualWidth 与无限大的 MaxWidth，这种断言必然成立。删除无效断言和与无限上限的多余 Math.Min，保留最大尺寸属性、真实最大化、最小尺寸、控件可见及超长音标检查。
- 确认无效 Unicode 配置能被提示且原文件不被覆盖；现有代码已正确处理，只增加验证，不重复实现异常处理。

## 高级语法、抽象和重复

生产代码使用普通类、直接条件分支、循环、属性和短事件回调；没有 async/await、动态代码、泛型业务框架或模式匹配流水线。可空类型、using 资源释放、ICommand、WPF 依赖属性、少量委托和 Win32 结构直接服务于绑定、生命周期和平台操作，保留这些实际需要的机制，不做纯语法替换。

BigInteger 对应 schema_version 可为任意正整数的已确认要求；Unicode casefold 数据保证词库重复判断和进度键规则一致，不能用简单 ToLower 替换。

扫描时校验每本词库、打开时重新读取选中词库存在少量重复，当前没有性能故障证据。暂不引入缓存和失效逻辑，以免增加状态和耦合。英美音标显示、按钮和段落排版保留必要局部重复，不增加通用字段框架。词库 name、description、schema_version 虽不控制下拉显示，仍是已接受的元数据，保留读取和类型校验。
